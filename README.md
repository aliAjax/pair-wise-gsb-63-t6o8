# 游乐设施日常检验与缺陷闭环平台

基于 Vue3、Naive UI、Pinia、Vue Router、TanStack Query、Axios、WebSocket 和 Vite 的独立前端工程。数据默认保存在 localStorage，无需后端即可演示。

## 业务闭环

- **标准发布 → 检验执行（版本冻结）**
  - 检验标准按设备型号（AM/RC/CR/WF…）发布版本，发布后内容冻结。
  - 新任务按创建时刻的最新发布版本执行，限值随任务快照保存。
  - 已开始的任务仍按开始时那版判定；之后再发布新标准不会串改进行中任务，页面会提示存在新版但本任务沿用旧版。
  - 旧记录迁移时按设备型号补默认版本；没有适用版本的记录进入「待复核」、保持停用，可人工补绑版本后再录入。
- **两窗口并发保存 → 冲突修订**
  - 记录带乐观锁版本（R*）。两个窗口基于同一版本先后保存时，后保存窗口保留自己的输入。
  - 先保存窗口的整改责任人、处置结论、证据编号和逐项读数自动留档为「冲突修订」，双方证据按编号合并，不丢失。
  - 冲突修订可逐条把先保存一方的责任人/处置结论/逐项读数并回记录。
  - 看板调度（仅改责任人）与现场保存分离，不覆盖现场记录；跨标签页通过 storage 事件同步。
- **缺陷处置 → 复测放行**
  - 泳道覆盖需整改、整改中、待复测、停用、待复核、已关闭。
  - 复测按任务冻结版本的限值判定：失败则继续停用并自动登记下一次复测日期；全部通过才解除停用、恢复开放并关闭任务。
- **判定依据可追溯**
  - 详情页沿「标准版本 → 冲突修订 → 复测记录」展示每次判定依据，可导出依据包 JSON。
  - 审计时间线为每条操作标注所依据的标准版本，并可按标准发布/冲突/复测筛选。

## 页面

1. 检验总览：新建任务（选择/输入设备型号，自动冻结当前版本）、筛选、统计。
2. 标准发布：按型号编辑发布新版本、查看版本历史与限值。
3. 缺陷处置：风险泳道、冲突工单、待复核与停用/复测标记。
4. 任务详情：逐项检验（冻结限值+自动判定）、证据编号、冲突修订核对并回、复测录入与放行。
5. 判定依据审计：版本/冲突/复测完整时间线。

## 启动

```bash
npm install
npm run dev
```

访问 `http://localhost:18463`。

并发冲突演练：打开任一任务详情 → 点击「演练：模拟另一窗口（晚班）先保存」→ 直接点「保存本窗口记录」，即可看到冲突修订留档与证据合并。
